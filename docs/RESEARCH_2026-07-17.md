## 1. v1（旧実装）の実態調査

### 1.1 構成

- エントリ: `main.py` → `Transcriber().transcribe_from_youtube(url, bpm)`
- パッケージ: `guitartab_transcriber/`
  - `youtube.py` — yt-dlp で bestaudio を WAV 抽出
  - `transcriber.py`（33KB） — 中核。Demucs 分離 → librosa BPM推定 → **Basic Pitch** 音符検出 → レイテンシ補正(-100ms) → 倍音補正v6 → パームミュート検出 → ノイズ除去 → ベロシティ正規化 → 音価調整 → 弦/フレット割当（コスト最小化）→ ポジション最適化
  - `tab_format.py`（14KB） — ASCII / JSON / matplotlib / SVG / LilyPond 出力
  - `types.py` — `Note` データクラス
- 依存: basic-pitch, librosa, soundfile, yt-dlp, matplotlib（+ 外部コマンドとして demucs, lilypond）
- 対象曲: B'z「ギリギリchop」117BPM（歪みエレキ・速弾き・パームミュート）

### 1.2 何が動いて、何が動かなかったか

**動いていた:**
- YouTube DL → Demucs（htdemucs_6s, 6ステム）分離 → Basic Pitch → LilyPond/SVG/PDF 出力まで、パイプライン自体は貫通していた（result.pdf 等の生成物あり）
- 開放弦（A2/D3）の検出は完全再現性あり
- 別リポジトリ `~/myspace/sound_stems/stems.py` は独立した完成度の高い Demucs 分離スクリプト（preview/full/two-pass モード付き）

**動かなかった:**
- **G3（pitch 55, 3弦開放相当）が全く検出できない** — Basic Pitch の根本的限界
- 高フレット音（11-13F）・中フレット音の検出困難
- ドラムビートへのグリッド量子化は不正確で、コード内で `# DISABLED` 化済み

### 1.3 精度の実態（最重要）

`FINAL_STATUS.md` は「80-98%、目標90%達成 likely」と記載しているが、同文書に **"Not Yet Tested"** と明記されており、初期5イテレーションの精度数値はすべて未検証の机上予測。

実測の推移（`iteration_XX_results.json`、人間製 ground_truth.json 比）:

| Iteration | 精度 | 備考 |
|---|---|---|
| 18 | 0% | 646ノート過検出 |
| 19-21 | 5.9% → 11.8% | |
| 23 | **29.41%** (5/17) | 音声オフセット27.5s発見時。マッチしたのは開放弦のみ |
| 24-25 | 17.6% / 29.41% | **人間製GTに対する実質的な到達上限** |
| 36-37 | 「100%」 | **無効な数値**。GTをシステム出力から逆算再生成した自己参照評価 |

つまり v1 の後半ループは「精度を上げる」のではなく「採点基準を自分の答案に合わせる」方向に暴走していた。`SYSTEM_LIMITATIONS.md` のみがこの実態を正直に記録している（保存済み）。

### 1.4 失敗の根本原因（5点）

1. **Basic Pitch のドメイン不一致** — 学習データ GuitarSet はアコースティックギターのみ。歪みエレキの倍音構造に対応できない
2. **評価の自己汚染** — ground truth をシステム出力から再生成
3. **未検証ヒューリスティックの積み上げ** — 約800行を「期待精度+N%」の机上積算だけで追加
4. **リズム量子化のドラム依存** — 不正確で無効化に終わった
5. **難曲1曲への過剰適合** — 段階的な難易度設計がなかった

## 2. ツール調査（2026年7月時点、Web検証済み）

### 2.1 audio → notes（音符検出）候補

#### MuScriptor 【第一候補】
- https://github.com/muscriptor/muscriptor（596★）/ https://kyutai.org/blog/2026-07-10-muscriptor/ / arXiv:2607.08168
- Kyutai × Mirelo、**2026-07-10 公開**。decoder-only Transformer による多楽器 audio→MIDI 転写。170k曲の実音源学習 + RL post-training
- **"distorted electric guitar"（短縮名 "dist"）が独立した楽器クラスとして公式サポート** — v1 失敗原因への直接対策。今回の調査で唯一の歪みエレキ明示対応モデル
- `pip install muscriptor`。重み small/medium/large（103M〜1.4B）が Hugging Face 公開
- ライセンス: コード MIT / **重み CC BY-NC（非商用限定）**
- リスク: 公開直後で実運用実績薄。**Apple Silicon 動作未確認（要実機検証）**。ギター単体の定量ベンチ非公開
- 多楽器同時転写のため、Demucs 分離を経ずに直接使える可能性もある（M0 で両ルート比較の価値あり）

#### basic-pitch 【ベースライン兼フォールバック】
- https://github.com/spotify/basic-pitch（約5.3k★, Apache 2.0）
- 最新 v0.4.0（2024-08）で機能開発は停止気味。Apple Silicon は **Python 3.10 限定**と公式明記
- 歪みエレキ不適は v1 で実証済みだが、軽量・枯れており、クリーン音源のベンチ基準線とクロスチェックに有用

#### YourMT3+ 【予備】
- https://github.com/mimbres/YourMT3（237★, GPL-3.0）/ arXiv:2407.04822
- PyTorch≥2.2（MPS対応）で Mac 動作可能性は MT3 より高いが、論文版コードは main 未統合の pre-release 状態。歪みギターのベンチなし

#### 非採用と理由
| 候補 | 理由 |
|---|---|
| MT3 (magenta/mt3) | 2022年から実質開発停止。JAX/T5X が重く Apple Silicon で不確実 |
| QMUL High-Res Guitar Transcription (arXiv:2402.15258) | 公式実装なし。派生の hf_midi_transcription は**モノフォニック専用**。**論文自身が「歪み/エフェクトは今後の課題」と明記** |
| TART (arXiv:2510.02597) | コード未公開（公開予定の記述もなし） |
| trimplexx/music-transcription | 学習済み重み配布なし（自前学習必須）。CUDA前提、実績薄（★13） |
| GAPS (QMUL) | クラシックギター特化 |
| cwitkowitz FretNet | GuitarSet のみ、重み配布なし |
| EGDB-PG / Tone-informed Transformer (arXiv:2504.07406) | 歪み汎化を専門に扱う研究だがコード公開未確認 |

参考: **GOAT Dataset**（2025-09）は歪み含むエレキギターのデータセット（モデル配布なし）。将来のファインチューニング素材候補。

### 2.2 notes/MIDI → tab（運指割当）候補

#### 自前 DP + gtrsnipe 参考 【採用方針】
- https://github.com/scottvr/gtrsnipe（★47, pip対応, 活発）— フレット幅・手移動・弦切替ペナルティのコスト関数を持つ MIDI→ASCII tab 変換。実装として堅実
- v1 `transcriber.py` の弦/フレット割当（開放弦ボーナス・ポジション移動ペナルティ・弦競合回避）は叩き台として流用価値あり
- 参考: https://github.com/jgollub1/guitar_dp（★5, MIT）— 古典的DPの参照実装（モノフォニック限定）

#### Open-Fret 【不採用】
- https://github.com/Sidmaz666/open-fret（★3, MIT, 7コミット）— Fretting-Transformer (arXiv:2506.14223, ICMC 2025) の**非公式**再実装。原著者の公式コードは存在せず
- **学習済み重み未配布**（DadaGP/SynthTab で自前学習が前提）、issue 無効化で動作報告確認不可 → 「堅実に動く」方針と不適合

### 2.3 出力形式の方針

1. **ASCII tab**（第一目標 — テキストで diff 可能なのでテスト・回帰検証しやすい）
2. MIDI（耳で検証できる）
3. MusicXML(Guitar Pro/MuseScore 連携)
- v1 の LilyPond 依存は廃止（外部コマンド依存が重く、デバッグ困難だった）
